# Database

PostgreSQL 16 + pgvector in production; SQLite is supported for tests and offline demos.
Schema is managed by Alembic (`backend/alembic/versions/`). The initial migration is
explicit (not autogenerated) so the vector extension, HNSW index and JSONB variant are
deterministic.

## Tables

All tenant-owned rows carry `college_id` (indexed). IDs are UUIDs; timestamps are UTC.

| Table | Purpose | Key columns / relationships |
| --- | --- | --- |
| `colleges` | Tenant root | `code` unique, `name`, `city`, `placement_date`, `is_active` |
| `users` | Students, officers, admins | `college_id → colleges`, `email` (unique per college), `role`, `branch`, `target_role`, `xp`, `streak_count`, `consent_share_analytics`, `onboarding_complete`, scrypt hash |
| `refresh_tokens` | Rotating sessions | `user_id`, `token_hash` (unique), `expires_at`, `revoked` |
| `consents` | DPDP audit trail | `user_id`, `purpose`, `granted`, `policy_version`, `created_at` |
| `resumes` | Uploaded files + parsed data | `user_id`, `storage_key`, `mime_type`, `size_bytes`, `status`, `used_ocr`, `pages`, `raw_text`, `parsed_data` (JSON) |
| `resume_analyses` | Score + tailoring | `resume_id`, `target_role`, `job_description`, `score`, `subscores` (JSON), `suggestions` (JSON, includes decisions), `missing_evidence` (JSON), `injection_flags` (JSON), `prompt_version`, `model` |
| `question_bank` | Retrieval corpus | `college_id` nullable (global), `role`, `topic`, `difficulty`, `prompt`, `ideal_answer`, `key_points`, `embedding vector(768)`, `is_active` |
| `rubric_versions` | Versioned rubrics | `college_id`, `version`, `label`, `criteria` (JSON), `is_active`; unique `(college_id, version)` |
| `interviews` | Interview session | `user_id`, `resume_id`, `role`, `status`, `current_round`, `rubric_version`, `prompt_version`, `model`, `overall_score`, `duration_seconds`, `hint_count`, `variance_flag`, `needs_review` |
| `interview_turns` | Transcript | `interview_id`, `idx`, `round`, `speaker`, `content`, `is_followup`, `hint_used` |
| `interview_scores` | Scoring audit | `interview_id`, `criteria` (medians JSON), `samples` (JSON), `overall`, `spread`, `variance_flag`, `rubric_version`, `prompt_version`, `model` |
| `usage_events` | Cost ledger | `user_id`, `college_id`, `feature`, `provider`, `model`, `input_tokens`, `output_tokens`, `cost_usd`, `created_at` |

Foreign keys cascade on user deletion; resume deletion cascades analyses; interview
deletion cascades turns/scores. `resumes.user_id` and `interviews.user_id` are indexed for
dashboard queries.

## Vector search

- Production: `question_bank.embedding vector(768)`, HNSW index with cosine distance.
  Retrieval is `ORDER BY embedding <=> :query LIMIT k`, filtered by `is_active`, role/topic
  and `(college_id = :tenant OR college_id IS NULL)`.
- SQLite: the portable `EmbeddingType` column stores JSON and cosine similarity is
  computed in Python. This keeps tests and offline demos working without pgvector.
- Embedding dimensions are fixed by `EMBEDDING_DIM` (default 768) and the migration.
  Changing models requires a new column, re-embedding and a backfill migration.

## Migrations

```bash
cd backend
PYTHONPATH=. ../.venv/bin/alembic upgrade head
PYTHONPATH=. ../.venv/bin/alembic current
PYTHONPATH=. ../.venv/bin/alembic revision --autogenerate -m "describe change"
```

Review every autogenerated migration: SQLite cannot run `CREATE EXTENSION` or HNSW, so the
initial migration branches on dialect and uses JSON for the vector column on SQLite. Add a
migration for every model change, test upgrade on a clean DB **and** on a populated copy,
and update this file.

## Indexing notes

- `users (college_id, role)` and `users (college_id, lower(email))` support login and
  officer lists.
- `interviews (user_id, started_at)` for history; `interviews (college_id, status)` for
  analytics.
- `usage_events (user_id, created_at)` and `(college_id, created_at)` for monthly rollups.
- `refresh_tokens (token_hash)` unique; expiry cleanup is a scheduled ARQ job.

## Data lifecycle

Retention is documented in [SECURITY.md](../SECURITY.md#dpdp-aligned-data-lifecycle):
resumes/transcripts 12 months, scores 24 months, usage 24 months, logs 30 days. Account
deletion removes storage objects first, then the user row; cascades remove all dependent
rows. Aggregate analytics remain, but no longer identify the deleted student.

## Backups and restore

- Enable managed daily backups + point-in-time recovery in production (Neon/Supabase/RDS).
- Test restore quarterly into a separate database and run
  `alembic current` + a dashboard query.
- Object storage needs versioning or a lifecycle backup for resumes during the retention
  window.
- Never copy production data into a laptop or CI. Use the seed scripts for demos.
